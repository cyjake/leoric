# Benchmarks

Run the model-compilation benchmark with:

```sh
npm run benchmark:model-compilation
```

The benchmark compares all three model paths: a direct registered `Bone` subclass, a model
generated by `realm.define('Name', attributes)`, and models compiled by `@Model()` and
`realm.define(Class, attributes)`. It measures construction, row hydration, and hot mapped
getter/setter access. It also measures the one-time work needed to compile a fresh definition.
Set `ITERATIONS`, `COMPILATION_ITERATIONS`, `RUNS`, or `WARMUP_RUNS` to override the defaults.

Result on Node.js 22.21.1 (Apple Silicon, 100,000 steady-state iterations, 20,000
compilation iterations, median of 9 runs):

| One-time operation | Direct | `@Model()` compiled | Realm compiled |
| --- | ---: | ---: | ---: |
| define/compile fresh class | 605 ns (1.00x) | 2,670 ns (4.41x) | 2,775 ns (4.59x) |

| Case | Generated | `@Model()` compiled | Realm compiled |
| --- | ---: | ---: | ---: |
| construct with values | 1.00x | 1.03x | 1.01x |
| instantiate row | 1.00x | 1.01x | 1.01x |
| getter hot path | 0.97x | 0.89x | 0.90x |
| setter hot path | 0.99x | 0.94x | 0.93x |

Ratios are time relative to the direct model. Compilation adds about 2.1 microseconds
once per model. The small steady-state differences include benchmark noise and JIT layout
effects; the conservative run measured construction within 3%, hydration within 1%, and no
getter/setter regression. Compiled models therefore avoid both the previous roughly 1.8x
construction penalty and the Proxy hot-path penalty, but `declare` remains preferable because
it avoids compilation entirely and preserves the original constructor and inheritance identity.

Compiled definitions contain native class fields, but their constructors are never executed.
All measured instances therefore use ordinary prototype accessors with no `Proxy` and no
per-instance class-field repair. Run the benchmark on the target Node.js release before
publishing results.
