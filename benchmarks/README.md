# Benchmarks

Run the model-compilation benchmark with:

```sh
npm run benchmark:model-compilation
```

The benchmark compares all three model paths: a direct registered `Bone` subclass, a model
generated by `realm.define('Name', attributes)`, and models compiled by `@Model()` and
`realm.define(Class, attributes)`. It measures construction, row hydration, and hot mapped
getter/setter access. Set `ITERATIONS`, `RUNS`, or `WARMUP_RUNS` to override the defaults.

Result on Node.js 22.21.1 (Apple Silicon, 100,000 iterations, median of 7 runs):

| Case | Generated | `@Model()` compiled | Realm compiled |
| --- | ---: | ---: | ---: |
| construct with values | 0.99x | 0.99x | 1.03x |
| instantiate row | 1.02x | 1.03x | 1.03x |
| getter hot path | 0.99x | 0.86x | 0.90x |
| setter hot path | 1.00x | 0.93x | 0.95x |

Ratios are time relative to the direct model. The small wins on some hot paths are benchmark
noise or JIT layout differences rather than expected improvements. The important result is
that compiled models no longer carry the previous roughly 1.8x construction penalty, while
getter and setter performance remains at direct-model speed.

Compiled definitions contain native class fields, but their constructors are never executed.
All measured instances therefore use ordinary prototype accessors with no `Proxy` and no
per-instance class-field repair. Run the benchmark on the target Node.js release before
publishing results.
